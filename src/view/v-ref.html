v-ref

Атрибут v-ref именует элемент, чтобы затем обратиться к нему напрямую через $refs внутри выражения обработчика события — без document.querySelector и без хранения ссылки на элемент в данных компонента.

В отличие от директив вроде v-show или v-text, значение v-ref не вычисляется как JS-выражение — это обычная строка-имя, под которым элемент становится доступен в $refs. 

<div v-data="{ }">
  <input v-ref="email" type="email" placeholder="you@example.com">
  <button @click="$refs.email.focus()">Перейти к полю</button>
</div>

Нажатие на кнопку вызывает $refs.email — DOM-элемент с атрибутом v-ref="email" — и сразу передаёт ему .focus(), как обычному элементу, полученному через querySelector.

$refs доступен в любом выражении

$refs, как и $el, $event и $root, доступен в любом выражении — не только в @событие, но и в значении v-text, v-show, :class и других директив (подробнее — на странице Полный синтаксис). Внутри метода, вызванного из выражения (как highlight() ниже), эти переменные доступны через this.$refs, this.$el и так далее — без явной передачи аргументом.

Сам атрибут v-ref при этом можно писать на одном элементе вместе с любой другой директивой — он ничего не меняет в её работе, просто добавляет элементу имя: 

<div v-text="label" v-ref="labelEl"></div>
<button @click="console.log($refs.labelEl)">Показать элемент в консоли</button>

Динамические имена через v-bind

Внутри v-bind ключ 'v-ref' работает так же, как и написанный прямо в разметке, но его значение можно вычислить — например, дать каждому элементу цикла v-each своё уникальное имя. 

Youla.data('taskList', () => ({
  tasks: [
    { id: 1, title: 'Написать отчёт' },
    { id: 2, title: 'Проверить почту' },
  ],

  row(task) {
    return {
      'v-ref': `task-${task.id}`,
    }
  },

  highlight(id) {
    this.$refs[`task-${id}`].scrollIntoView({ behavior: 'smooth' });
  },
}))

<ul v-data="taskList">
  <li v-each="task in tasks" v-bind="row(task)">
    <span v-text="task.title"></span>
  </li>

  <button @click="highlight(2)">Показать вторую задачу</button>
</ul>

highlight() обращается к this.$refs напрямую, поэтому click-выражение теперь просто highlight(2) — без передачи $refs аргументом. this внутри метода — те же реактивные данные компонента (tasks, row, highlight), что и в любом другом методе v-data, только с $el, $event, $refs и $root поверх них.

Один компонент — одна область видимости

$refs ищет элемент только внутри текущего компонента: если внутри него вложен ещё один элемент с собственным v-data, его v-ref-элементы в $refs родителя не попадают — так каждый компонент случайно не задевает разметку другого.

Если на странице повторить одно и то же имя v-ref на нескольких элементах одного компонента, $refs вернёт первый найденный при обходе DOM — держите имена уникальными в пределах компонента, как обычные переменные.
