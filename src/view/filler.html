Filler (v-filler)

Директива v-filler превращает обычный <input type="text"> в поле выбора цвета в духе Figma: квадратный образец цвета, поле HEX-значения и поле прозрачности (0-100%) — потянуть за подпись «%» можно прямо мышью, влево-вправо. Клик по HEX-полю открывает выпадающий список с ручным вводом и палитрой (список «цвет + название»), плюс свой набор цветов. Клик по квадратному образцу открывает полноценный диалог с кнопками «Заливка»/«Изображение» над образцом цвета: «Заливка» — это HSV + прозрачность с кнопкой копирования значения в буфер обмена, «Изображение» — поле загрузки одной картинки с выбором object-fit, поворотом на 90° и ползунками для CSS-фильтров brightness, contrast, saturate, grayscale, sepia, hue-rotate, invert и blur — каждый ползунок подставляет значение напрямую в соответствующую функцию CSS filter, без промежуточных понятий вроде «экспозиции» или «теней».

Значение директивы — необязательный объект опций, который передаётся напрямую конструктору Filler. Само поле всегда показывает цвет в HEX, независимо от формата, выбранного в диалоге (HEX / RGB / HSL). И выпадающий список, и диалог никогда не бывают уже самого поля — по ширине они всегда подстраиваются под него.

Опции вкратце

Опция Описание По умолчанию
alpha Стартовая прозрачность (0-100); если не задана, читается из data-alpha поля, иначе — 100. null
format Формат полей и кнопки копирования внутри диалога — 'hex', 'rgb' или 'hsl'. Само поле рядом с образцом цвета всегда остаётся HEX. 'hex'
palette Массив { name, hex } для списка «Библиотека» в выпадающем меню — сортируется по name при отрисовке, каждая строка показывает цвет и название вместе. встроенный набор именованных цветов
sources Какие кнопки типа заливки показывать над образцом цвета — 'solid' и/или 'image'. Если оставить только один тип, кнопки скрываются, а диалог сразу открывается на этом типе. ['solid', 'image']
customPaletteKey Ключ localStorage, под которым хранится свой набор цветов пользователя; null отключает сохранение между визитами. 'youla-filler-palette'
suffixText Текст после значения прозрачности; перетаскивание этой подписи мышью меняет значение. '%'
disabled Блокирует поле целиком — открытие диалога/списка, ввод и перетаскивание. false
onChange Функция (hex, alpha) => void, вызывается при любом изменении цвета или прозрачности. null
classes Переопределение CSS-классов внутренних элементов пикера. см. Filler.DEFAULTS.classes

Изоляция стилей выпадающего списка и диалога

Само поле (образец, HEX, «%») — обычная разметка страницы. А вот выпадающий список и диалог рендерятся внутри отдельного shadow root (режим open): стили страницы туда не проникают, а стили этих панелей не просачиваются наружу — даже если на странице случайно есть правило вроде button { all: unset }, содержимое диалога не пострадает.

Опция classes при этом работает как раньше — задаёт названия классов внутри панели. А вот переопределить их стили снаружи обычным селектором уже нельзя: вместо этого у каждого элемента панели есть атрибут part, повторяющий его класс (в том числе переопределённый через classes), и достучаться до него можно через ::part() с внешней стороны компонента: 

<style>
  /* сработает для любого v-filler на странице, у которого открыт диалог */
  div::part(filler-dialog) { border-radius: 12px; }
  div::part(filler-dialog-area) { height: 200px; }
</style>

Базовое использование

Начальный цвет и прозрачность читаются из value и data-alpha.

<input type="text" value="#FF6F59" data-alpha="80" v-filler>

Реакция на изменения

onChange получает актуальные HEX и прозрачность при любой правке — вводе HEX, перетаскивании ползунков диалога или значения «%». Кнопка «⧉» в диалоге копирует текущий цвет строкой в том формате, что выбран на вкладках (HEX/RGB/HSL), с учётом прозрачности.

Текущее значение: 

<input
  type="text"
  value="#2196F3"
  v-filler="{ onChange: (hex, alpha) => result = `${hex}, ${alpha}%` }"
>
<p>Текущее значение: <code v-text="result"></code></p>

Свой формат и своя палитра

Диалог можно открыть сразу в формате rgb, а список библиотеки — сузить до нужных брендовых цветов. 

<input
  type="text"
  value="#8F00FF"
  v-filler="{
    format: 'rgb',
    palette: [
      { name: 'Brand Purple', hex: '#8F00FF' },
      { name: 'Brand Teal', hex: '#0E7A6B' },
      { name: 'Brand Amber', hex: '#A85417' },
    ],
  }"
>

Заливка изображением

Кнопки «Заливка» и «Изображение» над образцом цвета переключают диалог между HSV-пикером и панелью загрузки картинки — как и в Figma, сам переключатель меняет тип заливки, а не просто вкладку диалога: пока активна «Изображение», квадратный образец показывает миниатюру картинки (обрезанную по образцу, с учётом поворота и прозрачности), а само поле вместо HEX показывает текст «Изображение» и становится нередактируемым — клик по нему, как и по образцу, открывает диалог. Текст локализуется через labels.imageSource (та же строка, что и на кнопке-переключателе) и labels.solidSource.

В панели «Изображение»: селект object-fit и кнопка поворота на 90° по часовой стрелке над полем загрузки; клик по уже загруженной картинке открывает выбор файла заново, чтобы её заменить, крестик в углу — убирает картинку совсем. Ниже — по одному ползунку на каждую функцию из Filler.IMAGE_FILTERS, и диапазон каждого ползунка ограничен ровно тем, что допускает сама CSS-функция — вплоть до значений на границе диапазона, а не только «в среднем разумных»:

  • brightness, contrast, saturate — 0-200%, нейтраль 100%. По спецификации отрицательные значения запрещены, а сверху функция не ограничена вовсе; 200% — это уже наш собственный, произвольный практический потолок для ползунка.
  • grayscale, sepia, invert — 0-100%, нейтраль 0% (она же нижняя граница). Отрицательные значения тоже запрещены, но здесь 0% и есть «выключено», поэтому середины диапазона как таковой нет — это обычные ползунки от края.
  • blur — 0-20px, нейтраль 0px (нижняя граница): отрицательная длина размытия невалидна для CSS в принципе.
  • hue-rotate — единственный, где отрицательные значения — не ошибка, а другой угол: hue-rotate(-90deg) ≠ hue-rotate(90deg). Диапазон -180…180°, нейтраль 0° — это единственное осмысленно-двустороннее значение и полный круг без повторяющихся углов.

Итоговая строка для filter собирается из значений ползунков напрямую — сам диапазон каждого ползунка уже не пускает значение, невалидное для соответствующей функции, так что подчищать его перед сборкой не нужно. Подписи ползунков берутся из labels.filters (по одному ключу на каждый фильтр, как в примере выше).

Заливка дорожки идёт не всегда от края: для brightness/contrast/ saturate/hue-rotate — от нейтрального значения (оно же середина их диапазона) к бегунку, цветом показывая сторону отклонения — коралловый влево, синий вправо; для остальных, у которых нейтраль совпадает с нижней границей (grayscale, sepia, invert, blur), это вырождается в обычную заливку от края — отклонение всегда в одну сторону, и всегда синим. Квадратная кнопка «Сбросить» — в левом верхнем углу поля картинки, зеркально крестику удаления в правом — но показывается только при наведении на картинку и только если хотя бы один ползунок сдвинут с нейтрального значения; сбрасывает все ползунки разом, саму картинку не трогая. Опция sources сужает набор кнопок над образцом цвета — например, оставить только загрузку изображения. 

<input type="text" value="#4C9FFE" v-filler>

С единственным доступным источником кнопки-переключатели не показываются:

<input type="text" value="#4C9FFE" v-filler="{ sources: ['image'] }">

Отключённое поле

<input type="text" value="#9E9E9E" data-alpha="40" v-filler="{ disabled: true }">
