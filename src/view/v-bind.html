v-bind

Смысл директивы — убрать из разметки нагромождение из v-*, @ и : атрибутов и вынести поведение элемента в JS. Никакого отдельного механизма для этого не требуется: набор биндингов — это обычное свойство внутри v-data, объект, ключи которого — имена атрибутов ('@click', ':aria-expanded', 'v-show', 'v-ref' или просто 'type'), а значения — то же, что вы написали бы в HTML напрямую: строка-выражение, метод с this в роли данных компонента, или обычное статическое значение. Разметка получает одну короткую ссылку — v-bind="имя", а определение остаётся переиспользуемым для любого числа элементов.

Определение через v-data

Опишите компонент через Youla.data(имя, callback) — как обычно, но добавьте в возвращаемый объект свойства с наборами биндингов. Каждый метод внутри такого набора получает this, указывающий на реактивные данные компонента, — точно так же, как методы Youla.data уже работают. 

Youla.data('dropdown', () => ({
  open: false,
  trigger: {
    '@click'() {
      this.open = true
    },
  },
  dialogue: {
    'v-show'() {
      return this.open
    },
    '@click.outside'() {
      this.open = false
    },
  },
}))

В разметке остаётся только ссылка на нужное свойство — trigger и dialogue объявлять в v-data отдельно не нужно, они уже часть данных компонента:

<div v-data="dropdown">
  <button v-bind="trigger">Открыть меню</button>

  <span v-bind="dialogue">Содержимое меню</span>
</div>
Содержимое меню

Каждый ключ в наборе биндингов обрабатывается так же, как если бы он был написан в разметке напрямую: @click регистрирует обработчик, v-show вызывается заново при каждом изменении данных и переключает видимость.

От того, к какому типу относится ключ, зависит, чего Youla.js ждёт от метода — возврата значения через return или нет.

Тип ключа Нужен return? Поведение
@событие (@click, @click.outside и т.п.) Нет Метод — обработчик. Вызывается один раз при срабатывании события ради побочного эффекта (обычно изменения this). Возвращаемое значение полностью игнорируется — писать return незачем.
v-директива, :атрибут и обычный атрибут (v-show, v-text, :class, type и т.п.) Да Метод — вычисляемое значение. Вызывается заново при каждом изменении связанных данных, и то, что он вернёт через return, становится значением, которое применяется к элементу. Без return метод вернёт undefined, и директива получит именно его — например, v-show скроет элемент (undefined ложно), а v-text очистит его содержимое.

Внутри метода-обработчика (@событие) this указывает на реактивные данные напрямую — запись в него сразу вызывает обновление. Внутри метода-вычисления (v-директива, :атрибут и т.п.) this дополнительно отслеживает, какие свойства вы читаете, чтобы знать, когда пересчитывать значение заново; такой метод предназначен для чтения и return, а не для записи в данные.

Строки-выражения вместо методов

Для простых случаев метод необязателен — значением может быть обычная строка-выражение, как в атрибуте :атрибут="выражение". Она пересчитывается при каждом изменении связанных данных ровно так же, как и метод. 

Youla.data('saveButton', () => ({
  saving: false,

  action: {
    ':disabled': 'saving',
    '@click': 'saving = true',
    'v-text': "saving ? 'Сохраняем...' : 'Сохранить'",
  },
}))

<div v-data="saveButton">
  <button v-bind="action">Сохранить</button>
</div>

Значение-строка на ключе с префиксом v-/@/: — всегда выражение. Ключ без префикса (здесь type) — всегда обычный статический HTML-атрибут, применённый один раз, без вычисления, точно как если бы вы написали его в разметке напрямую.

Параметризованные определения

Выражение в v-bind необязательно должно быть просто именем свойства — это обычное JS-выражение, поэтому им может быть и вызов метода с аргументом. Так одно определение превращается в фабрику наборов биндингов, различающихся только переданным значением. 

Youla.data('tabs', () => ({
  tab: 'profile',

  tabButton(name) {
    return {
      ':class': `{ active: tab === '${name}' }`,
      '@click': `tab = '${name}'`,
    }
  },
}))

<ul v-data="tabs">
  <li v-bind="tabButton('profile')">Профиль</li>
  <li v-bind="tabButton('settings')">Настройки</li>
</ul>
  • Профиль
  • Настройки

tabButton подставляет name в строки выражений через шаблонную строку — это происходит один раз, при вызове метода. А вот tab внутри самих строк остаётся именем свойства и вычисляется отдельно, заново при каждом изменении tab — поэтому активная вкладка переключается реактивно.

v-bind внутри v-each

Одно определение можно применить к каждому элементу списка, обращаясь внутри него к текущему элементу итерации — например, чтобы раскрасить бейджи приоритета задач, как в примере на странице v-each. 

Youla.data('priorityList', () => ({
  tasks: [
    { title: 'Написать отчёт', priority: 'high' },
    { title: 'Проверить почту', priority: 'low' },
    { title: 'Согласовать бюджет', priority: 'medium' },
  ],

  badge: {
    ':style': "{ color: task.priority === 'high' ? 'crimson' : (task.priority === 'medium' ? 'darkorange' : 'seagreen') }",
    'v-text': 'task.priority',
  },
}))

<ul v-data="priorityList">
  <li v-each="task in tasks">
    <span v-bind="badge"></span>
    <span v-text="task.title"></span>
  </li>
</ul>

Ключ badge — обычное свойство v-data, а не метод, поэтому у него нет доступа к this с текущим task — а вот строки-выражения внутри него получают task точно так же, как получил бы его любой обычный атрибут внутри v-each. Если бы вместо строк использовались методы, они бы не увидели task: методы получают только this с данными компонента, без переменных цикла.
