Условия отображения (builder)

builder — конструктор условной логики: группы правил, где группы объединены через ИЛИ, а правила внутри одной группы — через И. Ровно та же схема, что в условной логике ACF или Gravity Forms: «показать поле, если (условие 1 И условие 2) ИЛИ (условие 3)».

Каждое правило — это { field, operator, value }: что сравнивать, каким оператором и с каким значением. Сама структура ни к чему не привязана — submit() просто отдаёт готовый JSON, который дальше можно отправить на сервер, например через $ajax. 

<div class="demo example-builder" v-data="builder">
  <div class="builder-toolbar">
    <button type="button" @click="addGroup()">+ Группа (ИЛИ)</button>
    <button type="button" @click="submit()">Сохранить</button>
  </div>

  <div v-each="(group, key) in groups" class="builder-group">
    <div class="builder-group__header">
      <span class="builder-group__title" v-text="key === 0 ? 'Если' : 'Или, если'"></span>
      <button type="button" @click="addRule(key)">+ Правило (И)</button>
      <button type="button" class="is-ghost" @click="removeGroup(key)">Удалить группу</button>
    </div>

    <div v-each="(rule, index) in group.rules" class="builder-rule">
      <select :value="rule.field" @change="rule.field = $el.value">
        <option value="post">Тип записи</option>
        <option value="post_status">Статус записи</option>
        <option value="user_role">Роль пользователя</option>
        <option value="page_template">Шаблон страницы</option>
      </select>
      <select :value="rule.operator" @change="rule.operator = $el.value">
        <option value="===">равно</option>
        <option value="!=">не равно</option>
        <option value="contains">содержит</option>
      </select>
      <input type="text" :value="rule.value" @input="rule.value = $el.value" placeholder="Значение">
      <button type="button" class="builder-rule__remove" @click="removeRule(key, index)">×</button>
    </div>
  </div>
</div>

Важно при переносе разметки под свой дизайн: не ставьте кнопки «+ Группа» / «Сохранить» после списка групп (и «+ Правило» / «Удалить группу» — после списка правил внутри группы). Они должны идти раньше самого v-each, иначе пропадут при первом же рендере. В примере панель действий всё равно показана внизу, под группами — это сделано через CSS (order у flex-контейнера), а не через порядок в разметке.

Как подключить в своём проекте

Скопируйте разметку из вкладки HTML и повесьте v-data="builder" на общий контейнер — дальше конструктор работает сам, без дополнительного JS. Поля выбора — обычные <select>/<input>, так что набор условий (field) и операторов (operator) под свой проект меняется прямо в разметке — добавьте или замените <option>, ничего в самом компоненте трогать не нужно.

Шаблон нового правила (какие значения ставятся по умолчанию при «+ Группа» / «+ Правило») задаётся в default — измените его значения в исходнике компонента под свои условия и операторы, если стандартные (post/===) не подходят.

Что делать с результатом

submit() в примере просто печатает итоговый groups в консоль — в реальном проекте замените его тело на отправку этих данных на сервер, например через $ajax. Сам конструктор ничего не проверяет и не применяет условия — он только собирает их в JSON такого вида: 

[
  { "rules": [
    { "field": "post_status", "operator": "!=", "value": "contributor" },
    { "field": "user_role", "operator": "===", "value": "editor" }
  ] },
  { "rules": [
    { "field": "page_template", "operator": "contains", "value": "landing" }
  ] }
]

Применять условия — задача вашего проекта (на сервере или в браузере). Группы объединяются через ИЛИ, правила внутри группы — через И, так что проверка обычно выглядит так: 

function matches(groups, context) {
  return groups.some(group =>
    group.rules.every(rule => {
      const actual = context[rule.field];

      switch (rule.operator) {
        case '===':     return actual === rule.value;
        case '!=':      return actual !== rule.value;
        case 'contains': return String(actual).includes(rule.value);
      }
    })
  );
}

// matches(groups, { post_status: 'draft', user_role: 'editor' }) → true

Свойства и методы builder вкратце

Имя Когда использовать
groups Массив групп правил (ИЛИ между группами). У каждой группы — свой rules (И внутри группы)
default Заготовка нового правила — { field, operator, value }. Копируется при добавлении новой группы/правила
addGroup() Добавляет новую группу с одним правилом по умолчанию
removeGroup(index) Удаляет группу по индексу
addRule(key) Добавляет правило по умолчанию в группу key
removeRule(key, index) Удаляет правило index из группы key
submit() Отдаёт итоговую структуру условий — в этом примере просто в консоль, в реальном проекте замените на отправку на сервер
