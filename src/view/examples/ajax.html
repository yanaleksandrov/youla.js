Ajax и обновление фрагментов ($ajax)

Подходит для ajax запросов к любому API, и для проектов, где сервер сам решает, что на странице должно поменяться после ответа: какой фрагмент перерисовать, куда перейти, что показать в уведомлении. Подключается отдельным файлом после youla.js: 

<script defer src="youla.js"></script>
<script defer src="youla-ajax.js"></script>

Как это устроено

route — путь запроса (добавляется к baseURL, если это не полный http(s):// URL) и одновременно имя события ajax:route, которое диспетчеризуется на document, когда приходит успешный ответ.

Настройка

Расширение настраивается объектом Youla.ajax. Его можно задать в любой момент — настройки читаются при каждом запросе и накладываются на значения по умолчанию. 

document.addEventListener('youla:init', () => {
  Youla.ajax = {
    baseURL: 'https://api.example.com',
    csrf: { cookie: 'csrf_token', header: 'X-CSRF-Token' },
    errors: { field: '[data-error="{name}"]', wrapper: '.field' },
  };
});
Опция По умолчанию Назначение
baseURL '' префикс для относительных route
credentials true отправлять ли куки (withCredentials)
timeout 0 таймаут запроса в мс, 0 — без ограничения
headers {} заголовки для всех запросов
csrf.cookie / csrf.header 'XSRF-TOKEN' / 'X-XSRF-TOKEN' имя куки с токеном и заголовка, в котором он отправляется для мутирующих запросов на тот же origin; csrf: false отключает
errors.field '[name="{name}"]' селектор поля для ошибки, {name} заменяется ключом из ответа
errors.wrapper null селектор обёртки поля (через closest), получающей invalidClass; по умолчанию само поле
errors.anchor null селектор элемента (через closest), после которого вставляется текст ошибки; по умолчанию само поле
errors.messageClass 'ajax-error' класс элемента с текстом ошибки
errors.invalidClass 'is-invalid' класс невалидного поля или его обёртки; errors: false отключает ошибки у полей
messages.failed / messages.network английские тексты уведомления об ошибке сервера без описания и об обрыве сети

Метод запроса всегда указывается явно — короткими $ajax.get(...), $ajax.post(...), $ajax.put(...), $ajax.patch(...) и $ajax.delete(...); отдельного $ajax(...) без метода не существует. 

$ajax.get(route, payload, onProgress, options)
$ajax.post(route, payload, onProgress, options)
$ajax.put(route, payload, onProgress, options)
$ajax.patch(route, payload, onProgress, options)
$ajax.delete(route, payload, onProgress, options)
Параметр Значение
route путь запроса (или полный URL) и одновременно имя события ajax:route
payload необязательный объект — его пары добавляются в тело запроса вдобавок к полям элемента, от имени которого вызван $ajax
onProgress необязательный колбэк — вызывается при старте, во время загрузки файла и по завершении, с объектом { percent, loaded, total, start, progress, end, status, url, raw, json, blob } (raw — тело ответа как текст, json — тот же текст, разобранный как JSON, или null, если это не JSON)
options необязательный объект { headers, credentials, timeout } — переопределяет одноимённые настройки Youla.ajax для одного запроса

Тело запроса собирается из элемента, на котором вызван $ajax: для <form> — вся форма целиком (файлы из input[type="file"] уже включены), для любого другого поля — только его собственное значение (или выбранные файлы, если это одиночный input[type="file"]). Для GET те же данные, кроме файлов, передаются строкой запроса. Пока запрос выполняется, элемент и любые [type="submit"] внутри него получают класс is-load — оформление этого состояния (спиннер, затемнение) остаётся за CSS проекта.

Ответ сервера разбирается как JSON, когда это возможно, иначе промис получает необработанный текст. Если разобранное значение — объект вида { data }, дальше используется именно data: если это массив, каждый его элемент применяется к странице автоматически (см. таблицу действий ниже), а промис получает то же значение data. Если ответ — что угодно другое (обычный JSON-массив/объект без обёртки, строка, HTML), оно просто возвращается вызывающей стороне как есть — фрагменты не единственный сценарий использования.

Действия для обновления фрагментов

Каждый элемент массива data — это { target, ...действия }, где target — CSS-селектор, а остальные ключи — имена действий (через двоеточие можно задать задержку в миллисекундах, например "update:300"). Для действий, не привязанных к конкретному элементу страницы (notify, redirect, reload, changeURL) target можно не указывать вовсе.

Действие Что делает
updateзаменяет innerHTML цели
replaceзаменяет саму цель через outerHTML
removeудаляет цель из DOM
before, prepend,
append, after 		вставляют HTML рядом с целью — четыре позиции insertAdjacentHTML
valueустанавливает target.value (очистка полей формы)
classList.add / classList.removeпереключают класс
setAttributeзначение — пара [имя, значение]
removeAttributeзначение — имя атрибута
scrollTo / scrollIntoViewплавно прокручивают к цели
changeURLменяет адресную строку без перезагрузки (history.pushState)
redirect / reloadпереход по адресу или перезагрузка страницы
notify если на странице есть элемент u-data="notice" со своей очередью уведомлений, добавляет в неё запись — значение: строка с текстом, либо [текст, тип, длительность]

Сценарий 1: обновление фрагмента одним действием

Клик по кнопке отправляет запрос без формы — тело пустое, вызывающий элемент лишь определяет, куда добавить класс is-load на время запроса. Ответ обновляет счётчик и подсвечивает саму кнопку. 

<div u-data="{}">
  <button type="button" id="like-button" @click="$ajax.post('/demo/like')">
    <span id="like-count">★ 42</span> Нравится
  </button>
</div>

Сценарий 2: прогресс загрузки файла

Третий аргумент — колбэк прогресса — получает объект с полем percent на каждом шаге загрузки, чем удобно управлять элементом <progress>. 

<div u-data="{ percent: 0 }">
  <form @submit.prevent="
    $ajax.post('/demo/upload', {}, p => percent = p.percent)
      .then(() => percent = 0)
  ">
    <input type="file" name="file">
    <button type="submit">Загрузить</button>
    <progress :value="percent" max="100"></progress>
  </form>
  <div id="upload-result"></div>
</div>

Сценарий 3: форма и список в одном ответе

Один ответ сервера может нести сразу несколько независимых действий с разными целями и задержками: тут это добавление пункта в список и очистка поля формы. 

    <div u-data="{ text: '' }">
  <form @submit.prevent="$ajax.post('/demo/comment')">
    <input id="comment-input" u-prop="text" name="text" placeholder="Комментарий...">
    <button type="submit">Отправить</button>
  </form>
</div>
<ul id="comment-list"></ul>

    Сценарий 4: значение, отличное от фрагментов, и перехват ответа

    data необязательно должна быть массивом фрагментов — сервер вправе вернуть строку, число или объект, и $ajax просто передаст его вызывающей стороне. А поскольку ответ дополнительно диспетчеризуется как событие ajax:route, любой другой код на странице может подменить итоговое значение, вызвав event.detail.resolve(...) — раньше, чем это сделает сам метод. 

    <div u-data="{ outcome: '' }">
  <button type="button" @click="$ajax.get('/demo/echo').then(value => outcome = value)">
    Отправить
  </button>
  <div u-text="outcome"></div>
</div>

    // где-то ещё на странице, до клика:
document.addEventListener('ajax:/demo/echo', ({ detail }) => {
  detail.resolve(`перехвачено: «${detail.data}»`);
});

    Без перехватчика промис получил бы исходную строку «исходный ответ сервера» — на этой странице перехватчик выше уже зарегистрирован, поэтому результат приходит изменённым.

    Ошибки и повторные вызовы

    Если ответ пришёл с HTTP-статусом вне диапазона 200–299, либо запрос не смог выполниться (обрыв сети), промис $ajax отклоняется (reject) вместо того, чтобы молча обработать тело ответа как успешное — ошибку можно поймать обычным .catch(). Ошибки из ответа вида { errors: { имя: сообщения } } выводятся рядом с соответствующими полями формы, остальные (и message ответа) — уведомлениями в u-data="notice".

    Повторный вызов $ajax с того же элемента, пока предыдущий запрос ещё выполняется (например, двойной клик), сначала отменяет предыдущий — его промис отклоняется как «отменён», и он не сможет применить свои фрагменты к странице позже, в непредсказуемом порядке поверх результата нового запроса.
