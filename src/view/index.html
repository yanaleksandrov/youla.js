<% var data = { title: "Home Page" }; %> <%= _.template(require('./parts/header.html').default)(data) %>

Youla.js строится вокруг одной идеи: HTML на странице должен быть готов ещё до того, как загрузится JavaScript. За данные и разметку отвечает сервер, а библиотека — только за интерактивность поверх неё.

Это не ещё один способ отрисовать интерфейс на клиенте, а инструмент гидратации: Youla.js читает уже готовую разметку и оживляет её директивами, ничего не перерисовывая заново.

Поэтому основная задача разработчика — правильно получить и вывести данные на сервере. Youla.js включается уже после — без мерцания страницы и без проблем с индексацией контента.

Основная философия

Страница остаётся читаемой и рабочей, даже если JavaScript не загрузился или отключён — ссылки и формы работают как обычный HTML, а не как пустой контейнер в ожидании скрипта.

Поисковые роботы и парсеры соцсетей видят готовый контент сразу, а не пустой <div>, который нужно дождаться и выполнить, чтобы получить текст страницы.

Модификатор .lazy у v-each и v-prop, а также синхронизация атрибута hidden у v-show — прямое следствие этого подхода.

Youla.js не трогает то, что сервер уже отрисовал верно, а не гасит и не заменяет контент при инициализации, как это часто устроено в клиентских фреймворках.

Библиотеке не нужен виртуальный DOM и сравнение деревьев — она читает конкретный элемент и директиву на нём, поэтому клиентский код маленький и работает с любым бэкендом.

Чем это отличается от Alpine.js и Vue.js

Alpine.js устроен похоже: директивы прямо в разметке, без сборки. Но для борьбы с мерцанием он прячет разметку атрибутом x-cloak и правилом display: none.

Пока JS не загрузился, содержимое буквально скрыто от пользователя и краулера. Youla.js, наоборот, ничего не прячет по умолчанию — сервер уже показал правильный контент.

Vue.js в типичной настройке рендерит интерфейс полностью на клиенте: исходный HTML — пустой контейнер, а разметка появляется только после загрузки и выполнения JS-бандла.

Серверный рендеринг в Vue требует отдельной инфраструктуры (Node.js, Nuxt) и «гидратации» — сверки серверного и клиентского результата, которая может расходиться и требует отладки.

У Youla.js один путь рендеринга — тот, что уже настроен на вашем бэкенде. Гидратация здесь не отдельный режим сборки, а единственный сценарий работы библиотеки.

Установка

Youla.js пока не публикуется как npm-пакет — библиотеку нужно собрать из исходников репозитория самостоятельно. Это займёт пару минут.

Клонируйте репозиторий

git clone https://github.com/yanaleksandrov/Youla.js.git
cd Youla.js

Установите зависимости и соберите проект

npm install
npm run build

После сборки в папке dist появятся файлы youla.js и минифицированный youla.min.js.

Подключите библиотеку на странице

<script src="dist/youla.min.js"></script>

Youla.js сама найдёт на странице все элементы с атрибутом v-data и инициализирует их — вызывать что-либо вручную не требуется.

Общая рекомендация

Держите JavaScript отдельно от разметки. Простое состояние удобно описывать прямо в v-data="{ ... }". Но как только логики становится больше, выносите её в отдельный JS-файл, а не разрастайте атрибут.

Youla.data(имя, callback) регистрирует именованный компонент со своими данными и методами — в разметке остаётся только короткая ссылка на имя, а не весь объект целиком.

Youla.method() делает то же самое для переиспользуемых функций: результат доступен как $имяМетода в любом выражении, без копирования одной логики по всей разметке.

Пример с Youla.data() — на странице Примеры, а полный список специальных переменных вроде $имяМетода — в таблице выше.

<%= _.template(require('./parts/footer.html').default)(data) %>
