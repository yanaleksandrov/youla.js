v-bind

Пока состояние компонента — пара плоских свойств, объектный литерал прямо в атрибуте v-data="{...}" остаётся самым коротким и понятным путём. Но как только в задаче появляется повторяющаяся логика, сложные проверки, или богатый функционал, расписывать её в каждом выражении - становится многословно и хрупко: любое изменение поведения приходится аккуратно повторять во всех местах, где она встречается.

Директива v-bind собирает несколько v-*, @ и : атрибутов элемента в один именованный набор — обычный объект внутри v-data. Так поведение элемента переезжает из разметки в JS.

Ключи объекта — имена атрибутов ('@click', ':aria-expanded', 'v-show' или 'v-ref'), а значения — то же, что вы написали бы в HTML напрямую: выражение, метод или статическое значение. В разметке остаётся одна короткая ссылка — v-bind="имя", а само определение можно переиспользовать для любого числа элементов на странице, без копирования.

При этом v-bind лучше использовать только для того, что действительно требует динамики. Каждый binding участвует в обработке реактивных данных и может пересчитываться при их изменении. Поэтому неизменяемые свойства разумнее задавать непосредственно в HTML: например, если кнопка всегда имеет type="button", нет смысла выносить его в v-bind. А вот динамические свойства и поведение — например, :disabled или @click — как раз подходят для такого набора.

Определение через v-data

Опишите компонент через Youla.data(имя, callback) как обычно, но добавьте в возвращаемый объект отдельные свойства, каждое из которых станет набором биндингов.

Каждый метод внутри набора получает this, указывающий на реактивные данные компонента, — точно так же, как и обычные методы Youla.data, объявленные на верхнем уровне.

В разметке остаётся только ссылка на нужное свойство — trigger и dialogue объявлять в v-data отдельно не нужно, они уже часть данных компонента, возвращённых callback:

Содержимое меню 
<div v-data="dropdown">
  <button v-bind="trigger">Открыть меню</button>

  <span v-bind="dialogue">Содержимое меню</span>
</div>

Youla.data('dropdown', () => ({
  open: false,
  trigger: {
    '@click'() {
      this.open = true
    },
  },
  dialogue: {
    'v-show'() {
      return this.open
    },
    '@click.outside'() {
      this.open = false
    },
  },
}))

Каждый ключ в наборе биндингов обрабатывается так же, как если бы он был написан в разметке напрямую: @click регистрирует обработчик, v-show вызывается заново при каждом изменении данных и переключает видимость.

От того, к какому типу относится ключ, зависит, чего Youla.js ждёт от метода — возврата значения через return или простого выполнения побочного эффекта.

Тип ключа Нужен return? Поведение
@event (@click, @click.outside и т.п.) Нет Метод — обработчик. Вызывается один раз при срабатывании события ради побочного эффекта (обычно изменения this). Возвращаемое значение полностью игнорируется — писать return незачем.
v-директива, :attribute и обычный атрибут (v-show, v-text, :class, type и т.п.) Да Метод — вычисляемое значение. Вызывается заново при каждом изменении связанных данных, и то, что он вернёт через return, становится значением, которое применяется к элементу. Без return метод вернёт undefined, и директива получит именно его — например, v-show скроет элемент (undefined ложно), а v-text очистит его содержимое.

Внутри метода-обработчика (@event) this указывает на реактивные данные напрямую — запись в него сразу вызывает обновление связанной с ним разметки на странице.

Внутри метода-вычисления (v-директива, :attribute и т.п.) this отслеживает читаемые свойства, чтобы знать, когда пересчитывать значение — такой метод только для чтения и return, а не для записи данных.

Используйте обычную функцию или сокращённую запись метода ('@click'() {...}), а не стрелочную — стрелочные функции не получают this компонента, и Youla.js выведет предупреждение в консоли.

Строки-выражения вместо методов

Для простых случаев метод необязателен — значением может быть обычная строка-выражение, как в атрибуте :attribute="выражение". Она пересчитывается при каждом изменении связанных данных ровно так же, как и метод. 

<div v-data="saveButton">
  <button type="button" v-bind="action">Сохранить</button>
</div>

Youla.data('saveButton', () => ({
  saving: false,

  action: {
    ':disabled': 'saving',
    '@click': 'saving = true',
    'v-text': "saving ? 'Сохраняем...' : 'Сохранить'",
  },
}))

Параметризованные определения

Выражение в v-bind не обязано быть просто именем свойства — это обычное JS-выражение, поэтому подойдёт и вызов метода с любым числом аргументов, как обычный вызов функции.

Так одно определение превращается в фабрику наборов биндингов, различающихся только переданным значением — удобно для вкладок и похожих переключателей.

  • Профиль
  • Настройки
<ul v-data="tabs">
  <li v-bind="tabButton('profile')">Профиль</li>
  <li v-bind="tabButton('settings')">Настройки</li>
</ul>

Youla.data('tabs', () => ({
  tab: 'profile',

  tabButton(name) {
    return {
      ':class': `{ active: tab === '${name}' }`,
      '@click': `tab = '${name}'`,
    }
  },
}))

tabButton подставляет name в строки выражений через шаблонную строку — это происходит один раз, в момент вызова метода, а не при каждом обновлении данных.

А вот tab внутри самих строк остаётся именем свойства и вычисляется заново при каждом изменении tab — поэтому активная вкладка переключается реактивно.

v-bind внутри v-each

Одно определение можно применить к каждому элементу списка, обращаясь внутри него к текущему элементу итерации — например, чтобы раскрасить бейджи приоритета задач, как в примере на странице v-each. 

<ul v-data="priorityList">
  <li v-each="task in tasks">
    <span v-bind="badge"></span>
    <span v-text="task.title"></span>
  </li>
</ul>

Youla.data('priorityList', () => ({
  tasks: [
    { title: 'Написать отчёт', priority: 'high' },
    { title: 'Проверить почту', priority: 'low' },
    { title: 'Согласовать бюджет', priority: 'medium' },
  ],

  badge: {
    ':style': "{ color: task.priority === 'high' ? 'crimson' : (task.priority === 'medium' ? 'darkorange' : 'seagreen') }",
    'v-text': 'task.priority',
  },
}))

Ключ badge — обычное свойство v-data, а не метод, поэтому у него нет собственного доступа к this с данными текущего элемента итерации внутри цикла v-each.

Строки-выражения внутри него всё же получают task — так же, как получил бы его любой обычный атрибут, объявленный прямо внутри директивы v-each на странице.

Если бы вместо строк использовались методы, task они бы не увидели: методы получают только this с данными компонента, без доступа к переменным цикла v-each.
