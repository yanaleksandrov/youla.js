Жизненный цикл

Жизненный цикл — это путь, который проходит Youla.js от подключения скрипта на странице до постоянной фоновой работы: от поиска компонентов в разметке до реакции на каждое изменение данных. Разобравшись в этих этапах, легче понять, в какой момент выполняется ваш код и почему интерфейс обновляется не мгновенно в строке с изменением данных, а чуть позже — "на следующем тике".

Коротко: пять этапов

Этап Когда происходит
1. Запуск библиотеки Скрипт подключён на странице, в document отправляется событие youla:init
2. Ожидание DOM Youla.js дожидается DOMContentLoaded, если документ ещё не загружен полностью
3. Обнаружение компонентов Поиск всех элементов с атрибутом v-data в документе
4. Инициализация компонента Разбор v-data, восстановление значений .local/.cookie, первый проход по разметке
5. Реактивные обновления При каждом изменении данных — точечное обновление затронутых директив и атрибутов

1. Запуск библиотеки

Как только скрипт библиотеки выполняется на странице, Youla.js сразу же — ещё до того, как дождётся полной загрузки DOM — отправляет в document событие youla:init. Это удобная точка для стороннего кода, которому нужно узнать о старте библиотеки как можно раньше: 

document.addEventListener('youla:init', () => {
  console.log('Youla.js начинает работу');
});

2. Ожидание DOM

Дальше библиотека дожидается события DOMContentLoaded, если документ на момент запуска ещё не был полностью загружен. Это гарантирует, что к моменту поиска компонентов вся разметка страницы уже существует в DOM — не нужно вручную оборачивать код в DOMContentLoaded или откладывать подключение скрипта до конца <body>.

3. Обнаружение компонентов

Дождавшись готовности DOM, Youla.js ищет по всему документу элементы с атрибутом v-data — именно этот атрибут отмечает корень компонента (подробнее — на странице v-data). Каждый найденный элемент становится независимым компонентом со своими собственными данными.

Если внутри одного компонента встречается вложенный элемент с v-data, он не считается частью родителя — это отдельный, самостоятельный компонент со своей областью данных: 

<div v-data="{ parent: true }">
  ...
  <div v-data="{ child: true }">
    <!-- отдельный компонент со своими данными, «parent» здесь не виден -->
  </div>
</div>

4. Инициализация компонента

Для каждого найденного компонента Youla.js выполняет несколько шагов подряд, ещё до того, как что-либо появится на экране:

  1. Вычисляет выражение из v-data="{ ... }" как обычный JavaScript-объект — именно он станет данными компонента.
  2. Если внутри компонента есть поля форм с директивой v-prop, для них выставляются значения по умолчанию, а затем — если указаны модификаторы .local или .cookie — поверх подставляются ранее сохранённые значения из localStorage или cookie.
  3. Готовые данные оборачиваются в реактивный объект (Proxy), который отслеживает каждое чтение и изменение свойств.
  4. Youla.js проходит по всей разметке компонента один раз: находит директивы, обработчики событий (@событие) и привязки атрибутов (:атрибут), и применяет их — например, подписывается на события кнопок или подставляет начальный текст в v-text.

Именно во время этого первого прохода срабатывает специальное событие @load — оно вызывается сразу, как только элемент инициализирован, что удобно для действий, которые должны произойти один раз при появлении элемента: 

<div v-data @load="console.log('Компонент готов к работе')">...</div>

Подробнее про @load, @intersect и остальные события — на странице События.

5. Реактивность: как выглядит цикл обновления

После инициализации компонент продолжает жить: любое присвоение значения свойству в данных компонента (например, count++ в обработчике клика) перехватывается реактивным объектом и запускает обновление — но не мгновенно построчно, а чуть позже, на следующем "тике". Это сделано намеренно: если в одном обработчике меняется сразу несколько свойств, все изменения собираются вместе и приводят только к одному проходу по разметке, а не к нескольким: 

<button @click="a++; b++; c++">Изменить сразу три свойства</button>

Во время обновления Youla.js заново проходит по разметке компонента и пересчитывает выражение каждой директивы и привязки, но применяет результат только там, где выражение действительно зависит от изменившегося свойства. Так библиотека избегает лишней работы с DOM, не трогая элементы, которые от изменения никак не зависят.

Компоненты, добавленные динамически

Поиск компонентов не ограничивается разметкой, которая была на странице в момент запуска. Youla.js также следит за появлением новых элементов в <body> и автоматически инициализирует любой добавленный позже элемент с атрибутом v-data — точно так же, как и при первой загрузке страницы. Это значит, что разметку, вставленную, например, после AJAX-запроса, не нужно инициализировать вручную: 

fetch('/partial.html')
  .then(response => response.text())
  .then(html => document.body.insertAdjacentHTML('beforeend', html));
<!-- если во вставленном html есть v-data, компонент оживёт сам -->

Чего в жизненном цикле пока нет

В отличие от некоторых других библиотек с похожим API, у Youla.js пока нет отдельного хука на удаление компонента (аналога "unmounted"). Если элемент с v-data удаляется из DOM, его слушатели событий не отписываются автоматически — особенно это касается модификаторов .window, .document и .outside, которые вешают слушатель не на сам элемент, а на window или document. Держите это в уме при частом удалении и пересоздании одних и тех же компонентов на странице.

<%= _.template(require('./parts/footer.html').default)(data) %>
