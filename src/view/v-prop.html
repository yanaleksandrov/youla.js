v-prop

Поведение директивы v-prop зависит от того, на каком элементе она объявлена:

  • на поле формы (input, select, textarea) — это двусторонняя привязка: значение поля попадает в данные компонента, а изменение данных обновляет поле;
  • на любом другом элементе — это тоже двусторонняя привязка, только вместо значения поля используется содержимое: обычный текст через textContent, либо, с модификатором .html, разметка через innerHTML.

Такой подход позволяет не повторяться и сделать html представление более лаконичным — не нужно отдельной директивы, чтобы просто показать значение поля рядом с ним. Сравните 2 по смыслу идентичных подхода: 

<form v-data>
  <input type="text" value="Hello" v-prop="test">
  <span v-prop="test"></span>
</form>
 
<form v-data="{test: 'Hello'}">
  <input type="text" value="Hello" @keydown.delay.1ms="test = $el.value">
  <span v-prop="test"></span>
</form>

Во втором случае не требуется объявления в директиве v-data и события ввода.

Вывод содержимого

Если v-prop указан на элементе, который не является полем формы, значение связанной переменной выводится как содержимое элемента, а не как атрибут value. Привязка при этом остаётся двусторонней: начальное значение переменной (если она ещё не объявлена) читается из уже отрендеренного содержимого элемента, а дальнейшие изменения переменной обновляют это содержимое.

Текст (по умолчанию)

По умолчанию содержимое устанавливается через textContent — то есть HTML-теги внутри строки экранируются и всегда отображаются как обычный текст, даже если в строке есть символы < и >.

Привязка при этом работает в обе стороны: если переменная ещё не объявлена в v-data, Youla.js не затирает уже отрендеренное содержимое элемента пустой строкой, а, наоборот, забирает его как начальное значение переменной — точно так же, как для полей формы начальным значением служит атрибут value. Дальше элемент уже реагирует на изменения этой переменной как обычно. 

<div v-data>
  <button @click="username = 'Name'">Изменить имя</button>
  Имя: <strong v-prop="username">Yan Aleksandrov</strong>
</div>
Имя: Yan Aleksandrov

Как и любая другая директива, v-prop реагирует на изменение данных — разметку обновлять вручную не нужно. 

<div v-data>
  <button @click="count++">Плюс</button>
  <button @click="count--">Минус</button>
  Значение: <strong v-prop="count">0</strong>
</div>
Значение: 0

Поскольку теги экранируются, а не превращаются в реальные DOM-элементы, текстовый вывод безопасен для отображения непроверенного, пользовательского контента. 

<div v-data="{ comment: '<img src=x onerror=alert(1)> Отличная статья!' }">
  <div v-prop="comment"></div>
</div>

Как и в любую другую директиву, в v-prop можно передать произвольное выражение, а не только имя переменной — например, отформатировать число или собрать строку из нескольких полей. 

<div v-data="{ price: 4990 }">
  Цена: <strong v-prop="`${price.toLocaleString('ru-RU')} ₽`"></strong>
</div>
Цена:

Переносы строк и пробелы

Текстовый вывод вставляет содержимое как обычный текстовый узел, поэтому символы перевода строки в связанной строке не превращаются в <br> и никак не влияют на внешний вид без дополнительных css-правил. Чтобы переносы строк отображались, добавьте элементу правило white-space: pre-line (или pre-wrap, если нужно сохранить и пробелы).

HTML (модификатор .html)

Модификатор .html заставляет v-prop вставлять значение как HTML-код через innerHTML, заменяя текущее содержимое элемента, вместо экранированного текста. Начальное значение переменной при этом (если она ещё не объявлена в v-data) забирается из уже отрендеренного innerHTML элемента — так же, как это описано для текстового вывода выше.

⚠️ Опасность XSS

Используйте .html только для доверенного контента и никогда — для контента, предоставленного пользователем. Динамический рендеринг HTML третьими лицами может легко привести к уязвимостям XSS. 

<div v-data="{ username: '<strong>Yan Aleksandrov</strong>' }">
  Имя: <span v-prop.html="username"></span>
</div>
Имя:

Вывод реактивен, как и любая другая директива: содержимое элемента перерисовывается при каждом изменении связанных данных. Это удобно, например, для предпросмотра форматированного текста прямо во время ввода — в паре с двусторонней привязкой того же поля. 

<div v-data="{ markup: '<strong>Привет!</strong> Это <em>живой</em> предпросмотр.' }">
  <textarea v-prop="markup"></textarea>
  <div v-prop.html="markup"></div>
</div>

Как и в любую другую директиву, в v-prop.html можно передать произвольное выражение — например, собрать разметку из нескольких полей объекта прямо на месте. 

<div v-data="{
  product: { name: 'Наушники', price: 4990, inStock: true }
}">
  <div v-prop.html="`
    <strong>${product.name}</strong>
    <span style='color:${product.inStock ? 'green' : 'crimson'}'>
      ${product.inStock ? 'В наличии' : 'Нет в наличии'}
    </span> — ${product.price} ₽
  `"></div>
</div>

Вложенные директивы Youla.js не обрабатываются

v-prop.html лишь вставляет строку через innerHTML — он не запускает повторную инициализацию компонента для нового содержимого. Если вставленная строка содержит атрибуты вроде v-prop или v-each, они останутся в разметке как есть, никак не вычисляясь: ниже вы увидите буквальный текст {{ user.name }}, а не имя пользователя. 

<div v-data="{ user: { name: 'Ian' } }">
  <div v-prop.html="`<span v-prop='user.name'>{{ user.name }}</span>`"></div>
</div>

Если вставленный фрагмент должен быть по-настоящему интерактивным, оберните его в собственный элемент с атрибутом v-data — Youla.js подхватит его отдельно и проинициализирует как самостоятельный компонент, как только он появится в DOM.

Модификаторы

.html

Действует только на элементах, не являющихся полями формы: заставляет v-prop выводить значение как разметку через innerHTML вместо экранированного текста. Подробнее — в разделе «Вывод содержимого» выше.

.number

По умолчанию любые данные, хранящиеся в свойстве через v-prop, сохраняются в виде строки. Чтобы заставить Youla.js хранить значение как число в JavaScript, добавьте модификатор .number.

.trim

Используется для автоматического удаления начальных и конечных пробелов из вводимого значения. Это полезно при работе с текстовыми полями, чтобы избежать лишних пробелов в пользовательском вводе. В примере ниже модификатор trim исключает ввод любого пробела.

Если требуется удаление пробелов после завершения ввода, используй модификатор .lazy.

.local и .cookie

Позволяют автоматически сохранять значение привязанного свойства в куках или локальном хранилище и восстанавливать его при последующих загрузках страницы. Это удобно для хранения пользовательских предпочтений, например, темы оформления, заполненных полей формы или других параметров.

В этом примере пользовательские данные будут сохранены в хранилище куки и localstorage.

<form v-data>
  <div>Сохранение в local storage</div>
  <input type="text" v-prop.local="local">
  <div v-prop="local"></div>
  <br>
  <div>Сохранение в куках</div>
  <input type="text" v-prop.cookie="cookie">
  <div v-prop="cookie"></div>
</form>
